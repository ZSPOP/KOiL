# KOiL 油价数据库机制说明

> 记录 KOiL 油价数据库的完整逻辑机制，防止后续迭代遗忘。
> 任何机制改动请同步更新本文档、`CHANGELOG.md` 与 `API_SOURCES.md`（数据源侧）。
> 数据源权威清单/实测样例见工程根 `API_SOURCES.md`；本文档与 `OilPriceDbSyncer.kt` / `AppDatabase.kt` 顶部注释互为索引。

---

## 1. 数据模型

表 `koil_prices`，主键 `(province, grade, effectiveDate)`：

| 字段 | 说明 |
|---|---|
| province | 省份（31 个省/直辖市，`OilPriceDbSyncer.PROVINCES`） |
| grade | 油号：92号汽油 / 95号汽油 / 98号汽油 / 0号柴油 |
| effectiveDate | **生效日 = 权威窗口日 + 1 天**（窗口「24 时」生效 → 次日 0 点实际生效） |
| price | 元/L；**搁浅窗口 = 维持价（上一窗口价）** |
| source | 来源 URL（abapi / 窗口搁浅·維持(abapi) / 官方核验） |
| isVerified | 官方已核验标记 |
| isStranded | 0=调价窗口，1=搁浅窗口（窗口日到了但价格未变） |

> 表名 `koil_prices`，字段见上表；当前 schema 为 v1（库文件 `KOiL.db`）。任何表结构变更必须升 version 并补 Migration，禁止 `fallbackToDestructiveMigration`。

## 2. 锚点链

锚点 = 一个已知窗口日。**①②③④ 只提供单个锚点日期，⑤ 负责推算当年全年窗口日历**。

| 级 | 来源 | 取什么 | 备注 |
|---|---|---|---|
| ① | **xxapi**（v2.xxapi.cn/api/oilPrice） | 最近窗口生效日 − 1 天 | **优先**（同源互备主） |
| ② | **ruseo**（api.ruseo.cn/api/oilprice） | 最近窗口生效日 − 1 天 | 与 ① 同源互备（回退） |
| ③ | **abapi 全年曲线**（abapiAnchor） | 最近调价日（**生效日 − 3 天**） | 实测 18/18 与发改委公告吻合 |
| ④ | **发改委公告** | 公告标题年份+月日 = 权威窗口日（含搁浅） | 网页抓取，公告格式变化即抓取为空 → 自动跳过，不影响主链 |
| ⑤ | **本地推算**（calculateAdjustDates） | 从锚点推算当年全年窗口日列表 | 纯本地算法，断网可用 |

> ** 多源一致性可观测**：锚点命中来源（xxapi/ruseo/abapi/ndrc/无）落盘 `KOiL-price-db-last-anchor-source`；每次同步成功写组合快照 `KOiL-price-db-last-sources`（"锚点:xxapi · 今日价:abapi"），设置页油价库区域展示「同步来源」。

**配套缓存（不算级，但关键）**：
- 内存缓存（`cachedAdjustDates`）+ 持久化缓存（`settings.priceDbAdjustDates`，逗号分隔）：App 重启后复用上次已推算的窗口日历；
- **缓存命中即使 ①-④ 全失败也不空降级**（杜绝假生效日）；缓存命中时照常执行假日期清理；
- **跨年失效**：内存/持久化缓存首日年份 ≠ 今年 → 清缓存重算（跨年自动滚动到新年日历，当年口径从零重计，无需清库）；
- **锚点缺失时**：`getAdjustDates()` 返回空列表 → 调用方降级（seedProvince 用 abapi 原日期）；补灌链在日历就绪前不灌（防假日期纪律，启动任务 30s 轮询重试直至就绪）。

## 3. 窗口日历推算规则（⑤）

`calculateAdjustDates(anchor, holidaySet, workdaySet)`：

- 锚点按**「10 个工作日 ≈ 14 自然日 + 节假日顺延」**：
  - **向后顺推**：从锚点（若在本年）每 +10 工作日至当年末；
  - **向前倒推**：从锚点每 −10 工作日回溯至当年首调。
- 工作日判定：调休补班日（workdays）算工作日；周末非补班日不算；放假日（holidays）不算（chinese-days 数据：放假日 + 调休补班日）。
- 节假日数据来自 **chinese-days**（jsDelivr → unpkg → npmmirror 三 CDN 回退），拉取「去年/今年/明年」三年；某年缺失则按纯工作日推。
- 结果升序、含历史与未来窗口，写入 `settings.priceDbAdjustDates`（逗号分隔持久化）。
- 日期规范化 `OilPriceDateUtil.normalize`：支持 `yyyy-MM-dd` / `yyyy/MM/dd` / `yyyy年M月d日` / `M月d日` / `M-d`；无年份按当前年推断，月份早于当前月视为下一年；无法识别返回 null。

## 4. 灌库流程（seedProvince）

拉单省当年曲线（abapi range=year，实测返回约 220~222 点，覆盖近一年，含上一年）并写入：

1. **幂等**：按 `省|油号|生效日` 键跳过已存在（重灌/补灌不重复插）；
2. **变化点插入**：只存「价格有变化」的点（调价日）；生效日 = `adjustToWindow(abapi日期) + 1`（abapi 滞后日期 → 归并到 ≤ 它的最近权威窗口日，再加 1 天）；
3. **写入闸**：`eff > today` 一律跳过（库里永不出现未来生效日）；
5. **补搁浅**：对每个**已过窗口**，若「窗口日+1」无生效记录且无本次新增变化点 → 插入搁浅记录（`isStranded=true`）：
   - **维持价** = abapi 曲线中 **≤ 窗口日** 的最后一个价格点（不设当年下界）；
   - **首窗口搁浅**（如 1-06）：abapi 当年曲线该日前无点 → 回退到**上一年最后一个调价点（上年末价）**；

**触发**：`seedRemainingProvinces`（立即更新/定时更新尾部 + 启动兜底）：
- 每省独立拉取，单省失败只留缺口不阻塞其他省；`seedLock` CAS 防并发；4 路并行 + 组间 200ms 缓解 abapi 限速；
- **日历未就绪不灌**：`fillRemainingProvincesIfCalendarReady` 返回是否已执行，启动任务 30s 轮询重试（保留防假日期纪律）。

---

## 5. 一次性灌库 + 持续增量模型

- **首次联网灌库**：`initPriceDb`（库为空时灌默认省一整年曲线；不再内置油价快照）；其余省由 `seedRemainingProvinces` 后台补全；
- 之后**永不重灌**（幂等键保证）；
- 新窗口日到了 → **增量加记录**：调价（调价检测 verifyProvince 插入）或搁浅（补搁浅插入）；
- **跨年不清库**：`purge` 只清「当年 1-1~12-31 内的假日期」，**往年日期一律保留**，历史持续累加。

---

## 6. 假日期清理（purge）

`purgeIllegalEffectiveDates(dates)`：

- 白名单 = 当年窗口日历每个窗口日 + 1 天；
- **只删**：生效日在「当年 1-1 ~ 12-31」**且**不在白名单的记录（如降级灌入的 09-27）；
- **不碰往年**。
- 调用点：`getAdjustDates` 推算成功时、**缓存命中时**、设置页打开/刷新状态时（`purgeIllegalEffectiveDatesIfReady`）。

## 7. 统计口径

| 展示项 | 口径 |
|---|---|
| **調價 N**（设置页数据库卡） | 窗口日历中**今年已发生窗口日数（含搁浅）** = `adjustDates.count { it < today }` |
| **記錄 N** | 库内全量记录（变化点 + 搁浅窗口，`COUNT(*)`） |
| **上調/下調次数**（记录页汇总） | 库内 `isStranded=false` 记录中 diff>0.001 / diff<-0.001 的条数（首条有前值时计入，如 1-06 入库后 01-21 计上调） |
| **擱淺次数**（记录页汇总） | `records.count { it.isStranded }` |
| **淨漲跌 / 累計上調 / 下調金額** | 仅统计非搁浅调价的 diff 累加 |
| **缺口提示** | 各省覆盖窗口数 < threshold 或存在搁浅缺口 → 红条警示（提示补灌） |

## 8. 记录页展示口径（OilPriceDetailScreen / ViewModel）

- 数据源：`observeByProvinceGrade` 查库（升序），**直接包含搁浅记录**（无展示层补全）；
- **日期显示**：调价记录 = 生效日（如 10-16）；**搁浅记录 = 窗口日（生效日 − 1 天，如 10-15）**（与数据库卡「調整日」一致）；
- **搁浅行**：灰色日期/价格/标签 + 灰色「擱淺」chip + 尾部「維持 09-25 價格」；
- **首窗口搁浅**（keptFrom=null）：尾部显示「維持 上年價格」；
- **走势图**：价格序列含搁浅（同价 → 水平线），台阶正确；超过 60 点均匀抽样；
- **省份切换**：横向滑动 chips + 左右箭头。

## 9. 调价检测 / 更新机制

`checkAndUpdate(force)`（8 小时节流 + 自动更新开关 + 防并发 CAS）：

2. **只信任「数据日期 == 今天」的源参与今日核验**：主源滞后 → 跳过核验（窗口存档仍生效，不产生假调价记录）；
3. **搁浅判定**：采样价与库内最新价差 < `STRANDED_EPSILON`(0.005)：
   - **窗口日当天不下搁浅结论**：今天若是窗口日，白天价格未变只返回"价格待 24 点后生效"，不写 `lastWindowChecked=今天`；
   - **搁浅结论只在「窗口日次日」落账**：非窗口日重复检查不滚动版本号（否则会把 V 滚成检查日）；
   - 其余情况返回"非窗口日，正常维持"。
4. **变化检测 → 增量入库**：仅默认省核验（`verifyProvince`）：
   - 生效日 = 归并窗口日 + 1；窗口日历未就绪 → 跳过本次增量；
   - **写入闸**：只在 `eff == today`（真正生效日）才入库——非窗口日价格抖动（数据源四舍五入）不再写"上一窗口生效日"假变化点；真实调价由次日核验/灌库自然写入；
   - 单源有价即自动入库（真实调价必然变价；同价非搁浅假点由 purge 清理）。
5. **窗口滚动存档**：接口 `nextAdjustment` 文本 → 本地推算窗口日历下个未来窗口兜底；旧 next 已过 → 升级为 prev；过期预告直接作为 prev 存档（避免首次同步即永久缺 prev）。
6. **失败不锁 8h**：失败不写 `lastCheckAt`——失败若也打节流时间戳，一次瞬时失败就会把自动检测锁死 8 小时；失败后保持原时间戳，下次启动/周期 Worker 立即重试。
7. **定时更新**：约 8 小时一次（OilPriceSyncWorker）；通知开关控制推送（未授权静默）。
8. **启动兜底**：全国补灌（30s 轮询等日历就绪）+ 假日期清理。

### 调价通知

`notifyPriceChanges(context)`（受 `pricePush` 开关控制）：

| 通知 | 触发 | ID |
|---|---|---|
| **调价生效** | 默认省+默认油号最新生效日变化，**且价格实际变化**（prev==null 或 prev.price != newest.price——搁浅维持价不再误发"调价至同价"）；首次启用静默锚定不打扰 | 默认 |
| **窗口日前一天提醒** | 下一个未过期窗口 == 明天（幂等去重 `KOiL-price-last-window-reminded`） | 1002 |
| **窗口日当天提醒** | 今天 == 窗口日 → "今晚 24 时生效"（幂等去重 `KOiL-price-last-window-day-reminded`）；触发点 = 一次性 Worker（窗口日 00:05 精准调度 `scheduleWindowDayReminder`，REPLACE 策略）+ 启动/8h 周期兜底 | 1003（独立） |

## 10. 预测幅度


- **主源 EIA**（官方布伦特现货 RBRTE，免费 Key 可配，`eiaEnabled` 开关 + `eiaApiKey`）：
  - **两条发布链路**：v2 API（`api.eia.gov/v2/petroleum/pri/spt`，全历史）与 WPSR 价格表 JSON（`www.eia.gov/petroleum/prices/data/12_series/D/PET_PRI_SPT_S1_D.json`，免 Key、最近 6 个交易日）。两者 series 同为 `RBRTE`、单位同为 USD/bbl，**没有口径差**，但实测 v2 比 WPSR 慢约 3 天（2026-11-10：v2 停在 11-03、WPSR 已到 11-06）。处理方式是按日期合并、取较新值；增量只覆盖它自带的那几天，**不改写 v2 的整段历史**——EIA 修订旧值时，回测（读固定数据）与线上会悄悄分叉。增量请求失败静默退回纯 v2，功能不挂、只是数据旧几天。补齐前本轮幅度 -464 元/吨，补齐后 -846 元/吨（差在 11-04 单日跌 15.19 美元）；
  - **基准日** = 库内最近一条**非搁浅调价**的生效日（搁浅轮不重置基准——官方规则，基准仍锚上次真调价）；
  - **基准日吸附**：生效日 = 窗口日 + 1 天，且 abapi 锚点写作「生效日 − 3 天」，故把生效日吸附到「±3 天内最近的窗口日」再取基准——直接拿生效日当前移一天（实测 30 个窗口里 24 个的生效日本身是 EIA 交易日，金额偏差均值 26.0、最大 109.7 元/吨），硬减 1 天则对 abapi 记录仍偏；
  - **基准均值** = 上一期窗口跨度 (上一窗口日, 基准窗口日] 内 EIA 交易日均价——**按跨度取，不按「往前数 10 个交易日」**：跨国庆/春节的周期有 11~15 个交易日，固定前取会丢掉周期头部、把基准挪向末段（实测跨假期窗口偏差最大 90.3 元/吨）。网格里没有更早窗口时退回「往前数 10 个交易日」；
  - **本窗口均值** = (上一窗口日, 今天] 的 EIA 交易日均价，**只取窗口内交易日，不足 10 天不回补上一窗口**（回补会把上一窗口走势混进来，把幅度稀释到接近 0；实测某窗口窗口内仅 2 天，混入 8 天旧数据后幅度被稀释到 -91.5 元/吨（旧系数口径），仅用窗口内两天为 -678.6 元/吨）；
  - **国内假期计入规则**：国内放假日 EIA 照常交易 → **计入**（官方取整个计价周期跨度的均价，不是「国内上班那几天」的均价）；EIA 休市日本身无价格 → 不参与均值，**不 forward-fill**（重复同一收盘价会人为压低波动，正是本修复要消灭的错误）；
  - **幅度** = (本窗口均值 − 基准均值) × 7.33 桶/吨 × 汇率(CNY/USD)，**passthrough 系数 k = 1**（不拟合、不滚动、不分段）。旧实现是「变化率 × 56.5 元/吨」，而 56.5 只是（布伦特 108 美元、汇率 7.14）那天的快照：`56.5 = 0.01 × 7.33 × 7.14 × 108`——把汇率与油价一起冻在快照里，油价中枢一漂移就系统性失真（实测隐含系数在 23.4~69.5 之间漂，与单位换算口径差均值 74.9、最大 362.4 元/吨）；
  - **汇率取静态月表**（`UsdCnyMonthly`，ECB 日度汇率取月内工作日均值，2023-12 起）：月内汇率波动对幅度的影响 < 1%，不值得为此新增一个网络源与断网降级链，静态表还能保证回测与线上算的是同一套数；漏更月份自动回退到最近更早月份，任何输入都返回有限正数，绝不返回 0（否则金额会被静默算成 0）；
  - **k 不拟合的依据**：25 轮公告回测最小二乘 k = 0.978 ≈ 1、中位 1.167——用中位反而把 MAE 从 153.0 拉回 176.2；调控轮（04-07、09-11、09-24、10-29）是行政压价，**单向**（15 轮上调中 4 轮被压，8 轮下调 0 次托底）且调控幅度区间 435~830 与未调控的 75~1160 完全重叠，**既无阈值也无系数可拟合**，只能如实承认这部分偏差；
  - **回测口径（验收按 22 轮，剔未解释的 04-21）**：22 轮 MAE 133.5 / P90 265.8 / 方向 86.4%（门槛 ≤155 / ≤300 / ≥80%，达标）；含 04-21 的 23 轮为 MAE 153.0 / P90 300.4 / 方向 82.6%，其中 04-21 是单列未解释项（公告 −555 vs 机制 +0.5 元/吨），按定稿「未解释、不计门槛」，故 300.4 只作透明披露、不改门槛；改前同口径 23 轮为 MAE 194.2 / P90 504.0；
  - **分侧偏差（已知未修）**：剔除调控轮后，上调 11 轮平均 −120.7、下调 8 轮平均 +124.1；再剔 04-21 后下调 7 轮均值 +58.9、中位 +73.7、5/7 正偏 → 下调侧存在「少算约 60~75 元/吨」的非单调偏差，不能用一个系数修，暂留作已知误差；
  - 基准缺失（库内无任何非搁浅调价）→ 回退「本窗口 vs 上窗口」环比（仅方向参考）；窗口日历未就绪 → 回退「最近 10 vs 前 10」硬切。
  - **样本天数**：本窗口已计入的交易日数随窗口推进从 1 增到 10，UI 恒定标注「已计入 N 个交易日」——**不写 /10**：EIA 交易日数与国内工作日数本来不等（30 个窗口里 11 个 ≠10），写死 /10 会让用户误以为数据缺失。幅度随样本增加收敛，不标注会把小样本估算误读为完整窗口结论。
  - **搁浅门槛**：|幅度| < 50 元/吨 → 官方本轮**不作调整**（未调金额纳入下次累加或冲抵），UI 写「按机制测算：预计搁浅（幅度约 X 元/吨）」且**不显示**折合元/升（<50 元/吨 折不到 0.04 元/升，常四舍五入成 0.00）。不单独分支就会显示「预计下调约 0 元/吨」或「预计上调约 47 元/吨」，用户以为会调、公告却是「不调」。判定抽成 `forecastDirection()` 纯函数并有单测，边界取严格小于（正好 50 元属于要调）；
- **降级/直选腾讯**（qt.gtimg.cn 布伦特期货实时，免 Key）：单日 ΔP × 7.33 桶/吨 × 汇率 → 元/吨（粗估，UI 标「单日参考」，不冒充窗口幅度）；
- **任何源失败 → 返回 null**（UI 显示「待检测」，不显示假值）；
- **数据截至标注**：EIA 路径返回 `dataDate`（已用到的最后交易日），UI 标注「截至 MM-dd」。合并 WPSR 增量后通常比当天晚 0~3 个交易日；若上游整批未发，会一次晚更多——此时「已计入 N 个交易日」同步变小，两个数始终自洽，不需要另设「数据延迟」提示。
- **源端发布日**：增量链路的顶层 `release_date` 也透到 UI，写成「截至 11-06 · 源端 11-09 发布」。两个数分开是因为量纲不同：前者是「数据到哪天」，后者是「官方哪天发的」，实测相差 3 天。只给前者，用户会把「源端节奏」当成「App 坏了」；只给后者，用户不知道数据实际到哪天。三条不变量：`release_date` 格式是 `M/d/yyyy`（月日不补零，实测 `11/9/2026`）；一个价格点都没解析出来时不给（发布日没有指代对象）；发布日早于数据最后一天时不给（发布不可能早于数据日，出现即说明字段语义变了，照原样显示等于把未知说成具体日期）。增量失败时为 `null`，UI 该段整块不显示。

## 11. 数据库与版本边界

- 库文件 `KOiL.db`，当前 schema 为 v1，安装即按当前 entity 建表；后续任何 entity/索引变更必须升 version 并补 Migration；
- 不接管任何既有数据文件，当前无迁移代码、无版本回退路径；
- 禁止 `fallbackToDestructiveMigration`（清库式升级会丢数据）；
- WAL 模式（大批量写入不阻塞查询）；schema 导出到 `app/schemas/<version>/` 作为当前结构基准。

## 13. 已知边界与依赖

| 项 | 说明 |
|---|---|
| **数据源非官方** | abapi/ruseo/xxapi 均为第三方，价格与日期可能有 1-3 天滞后或细微偏差——**库逻辑已闭环，剩余不确定性来自数据源**（今日价只信任 updateDate==today，滞后即跳过核验） |
| 锚点极端退化 | ①-④ 全失败且无缓存 → 空降级（seedProvince 用 abapi 原日期）；⑤ 本地推算断网可用，锚点缺失概率极低；启动补灌 30s 轮询等待日历就绪 |
| abapi 只给当年数据 | 首窗口搁浅维持价取不到 → 该条跳过（保持现状，不给错价） |
| 各省缺窗口 | abapi 偶发缺某省某窗口 → 缺口红条提示补灌 |
| 全新安装断网 | 空库，联网后启动/立即更新自动补灌 |
| 跨年分年回看 | 库内保留历史，记录页尚未分年维度（2027 前可选做） |
| EIA 配额 | 免费 Key 约 1000 次/日；失败自动降级腾讯 |
